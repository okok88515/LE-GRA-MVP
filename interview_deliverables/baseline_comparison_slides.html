四個方法，兩個維度的差異

候選怎麼產生、用什麼評分——這兩個維度上的差異，決定了誰輸誰贏。

Method A

Proxy 評分法

k-means 產生候選（同你的方法），但用「群組人數 × 最低 CQI」加總平均的簡化公式評分——不接真實資源分配。

Method B

切割點 + 標準差門檻

依 CQI 排序後搜尋所有連續切割點，標準差低於門檻（初始 0.5，找不到就放寬）才納入候選，再用真實資源分配評分挑最高分。

k-means 產生候選，用考慮真實 RB 資源分配限制的精確效用函數評分——本輪所有比較都以此為分母。

機制分析

每個方法表現好壞的真正原因

不是「誰比較聰明」，是每個方法的候選產生方式跟評分機制，各自踩中或踩空了哪個真實限制。

不分組

最差之一

畫質卡死在全體 24 人裡最差的那一個；「fairness 最高」是假象——大家一起差，不是靠好的分組設計換來的公平。high·heavy 崩得最兇（−0.387），因為分散度大＋資源緊繃同時發生，卻完全不因應。

Method A

全場最差

Proxy 公式（人數×最低CQI）數學上機械性偏好拆更多組，完全不管 RB 夠不夠——資源緊繃時，拆組的額外資源分配成本直接反噬，甚至比「不分組」自己這個候選還差。Fairness 全場最低（0.78），因為拆出的小群組畫質落差被放大又沒被評分機制注意到。

Method B

情境依賴

標準差門檻意外讓「隔離離群者」的候選容易通過篩選，在 high dispersion＋輕/中負載時這招真的划算、能贏過已發表方法。但篩選邏輯本身很粗糙——「門檻一放寬到有東西通過就停」——同一個搜尋空間裡的真正最優解比它高出 0.095，證明問題出在篩選機制,不是搜尋空間不夠大。

已發表方法

參照基準

用真實 DP 評分，結構上保證「不會比不分組差」（k=1 本來就是候選之一）。但一維 k-means 最小化的是組內變異數，不是真正效用——遇到需要隔離少數嚴重離群者才划算的情境，k-means 常常找不到那個分法。且數學上保證只能產生 CQI 排序後的連續分組，看不到資源成本或 regret 上的非連續結構。

候選聯集

目前最佳

疊加的資源成本家族、regret 圖分群家族，都不受一維連續性限制，正好補上已發表方法的兩個盲點；用同一套精確 DP 評分器維持「不會更差」的保證。Fairness（0.921）逼近不分組的假公平，但 ADR 是它的 1.5 倍——是「品質好又不犧牲公平」的真平衡，不是用犧牲換來的數字。

連續切割上界

參照值，非方法

用嚴謹 DP 窮舉「CQI 排序連續切割」這整個受限家族，證明就算被困在這個家族裡，也能比任何啟發式搜尋（Method B、k-means）更好。反過來說：它比候選聯集實際結果還高（0.382 vs 0.361），代表候選聯集自己的 k-means／圖分群搜尋一樣是啟發式的，也還沒觸頂——這是誠實的、還有進步空間的訊號，不是矛盾。

穩健性檢查 · 換一把尺

換成原論文的 ADR 指標，結論會反轉

同一批真實資料、同一個 20-seed confirmatory 協議，只把評分函式換成原論文的純 ADR（未服務=0分，無切換懲罰）。

Method B 反轉勝出——在 ADR 指標下贏過已發表方法（+140.6，20 場全勝）也贏過候選聯集（+140.6 vs +77.4）。原因跟第 8 頁的 utility 拆解完全吻合：Method B 靠激進拆組換來的高畫質分數，在 log-utility 下被未服務跟切換懲罰蓋過去；但 ADR 不看這兩項——沒服務到只算 0 分（不是 −2），畫質忽高忽低也不扣分。拆組讓多數人吃到更高碼率，在純 ADR 下是純粹加分，沒有代價。這也解釋了新版 utility 加懲罰項的用意：不是為了讓候選聯集贏，是為了讓「犧牲部分使用者換平均碼率」這種行為現出原形。
總結

一句話版本

  • 01已發表方法在兩個不同維度贏過既有方法：評分機制（vs. Method A 的 proxy 公式）、候選產生效率（vs. Method B 的窮舉+門檻搜尋）——但這個結論是在 log-utility 底下成立，換成原論文的 ADR 指標，Method B 反而會贏。
  • 02Pooled 結果在 log-utility 下乾淨：已發表方法 20 場全勝兩個既有方法；但拆到情境層級，Method B 在高 dispersion + 輕/中負載其實會贏，換成 ADR 指標這個優勢還會擴大成全面反轉——結論會隨你怎麼定義「好」而改變，這是誠實揭露、不是矛盾。
  • 03新研究（候選聯集）在兩種指標下都贏過已發表方法，是全部方法裡唯一一個不管用哪把尺量都站得住腳的。
