Research Execution Plan

MBS Grouping 研究待辦 Roadmap

這份 roadmap 現在不再把重心放在「怎麼把 LE-GRA 硬推成主角」， 而是把研究主線收斂成一條更穩、更能交代、也更接近目前證據的方向： 用 `Offline teacher + DP` 當研究 backbone，主方法聚焦在 `resource-cost` 與 `multi-feature` grouping。

接下來的待辦，不是優先證明 learner 一定最強，而是優先把 feature-centric 方法線、對照實驗、與最終報告敘事收斂完整。

Updated: August 10, 2026

現在的研究定位

目前最可信的版本已經很明確： `resource-cost / multi-feature` 是主方法線，`LE-GRA` 保留為探索性支線。

研究 backbone

Offline teacher -> grouping comparison -> exact DP allocation

主方法

Resource-cost k-means、Multi-feature k-means、Offline teacher

LE-GRA 的位置

保留為 exploratory / appendix line，不再當主結論核心

主線任務

先把研究主軸收斂完整

1. 固定主比較矩陣

報告主文優先固定比較 `No grouping`、`CQI k-means`、 `Resource-cost k-means`、`Multi-feature k-means`、`Offline teacher`。 `LE-GRA` 保留為補充方法，不再作為所有實驗的唯一主角。

目的：避免主線分散 輸出：統一比較表與報告圖表

2. 收斂 feature 主線

優先整理 `CQI-only`、`resource-cost`、`multi-feature` 三條表示法的差異， 明確說清楚哪一條只是 baseline、哪一條是主方法、哪一條代表更完整的問題表示。

目的：把核心貢獻講清楚 輸出：ablation 與方法解釋段落

3. LE-GRA 改成補充分析

保留 learner 線，但定位改成探索性分析： 它可以用來說明哪些 regime 會讓 learned grouping 有額外價值， 不是用來撐整篇研究最主要的結論。

目的：保留先前投入的研究價值 輸出：appendix / exploratory section

下一步優先順序

以現在的研究判斷排序

Priority A：把主文故事寫穩

  • 把專案敘事改成「從 CQI-only 走向 richer feature-based grouping」。
  • 把 `Offline teacher + DP` 明確寫成評估 backbone。
  • 把 `resource-cost` 與 `multi-feature` 放在方法章節中心。

Priority B：保留關鍵對照

  • 保留 `q10/r4` 這種真的能拉開 `teacher - resource-cost` 差距的 corridor。
  • 保留 `r2c` 這種 teacher 會 split、但強 baseline 也能追上的 control family。
  • 讓報告同時呈現「什麼時候 feature-based 有效」與「什麼時候 learner 並不必要」。

Priority C：LE-GRA 只做有意義的補充

  • 不再把時間花在大量 learner-only 小 tweak。
  • 只保留能幫助解釋 regime、boundary、或 grouping-path failure 的結果。
  • 把負結果整理成「為什麼它不是通解」的研究收斂。

目前可直接做的事

不需要再重啟整條研究線

整理報告

  • 同步 overview / conclusion / roadmap / handoff 的主線說法。
  • 把「offline teacher 不用全域最佳解」的理由放在方法章節。
  • 把 `resource-cost` 為什麼更貼近真實問題寫成主要 insight。

整理實驗證據

  • 保留 `LE-GRA` 成功與失敗兩種 corridor 各一組，當補充分析。
  • 避免再用大量矩陣掩蓋真正重要的 regime-level insight。

現階段不優先做的事

避免再回到低報酬迴圈

先不要

  • 先不要擴大 seeds / Kmax / 大矩陣，只會讓整理成本上升。
  • 先不要再做 learner loss、selector、tie-break 類的小修小補。
  • 先不要把整份研究重新包裝成「LE-GRA 差一點就要成功」。
一句話主線：這個專案第一階段最重要的成果，不是做出一個穩贏 learner，而是證明 `resource-cost / multi-feature` 比 `CQI-only` 更接近真實 multicast grouping 問題。
