研究主線重整

從 CQI-only 分群走向 Resource-Cost 與 Multi-Feature 分群

這個專案現在的核心，不再是要證明 LE-GRA 是一個普遍優於所有 baseline 的 learner。 更準確的研究主張是：在 vehicular multicast 場景裡，只用當下的 CQI 來分群太粗， 而真正接近資源分配問題本質的，是 resource-cost 與 multi-feature 這類更豐富的分群表示。

換句話說，這一階段最重要的成果不是「學出一個萬用模型」，而是把問題定義重新校正： grouping 成敗的關鍵，往往先卡在 feature representation，而不是 learner 技巧。

目前研究定位

我們已經驗證 teacher + DP 評估骨幹，也已經看清楚 CQI-only 的侷限。 現階段最可信、最實用的主角方法，是 resource-cost k-means 與 multi-feature k-means。

一句話版本

  • Teacher + DP 是穩定的研究量尺。
  • 真正的突破點是 richer feature，而不是再硬推 learner。
  • LE-GRA 保留為探索支線，不再是主標題方法。
主問題

這份研究現在到底在回答什麼

原本直覺

最自然的 baseline 是用 CQI 分群。因為 CQI 反映通道品質，直觀上看起來就像 multicast grouping 最應該依賴的訊號。

後來發現

multicast 的難點不只是「誰訊號差」，而是「誰會讓整組付出更高的傳輸代價」。 只看單一 CQI，會把很多真正重要的差異壓扁。

現在答案

比起 CQI-only，resource-cost 與 multi-feature 更能描述真實的服務難度， 也更貼近最終的資源分配目標。

為什麼 CQI 不夠

真正的瓶頸是 feature 太薄，不只是模型太弱

同樣 CQI，不代表同樣成本

兩個使用者就算 wideband CQI 很接近，RB-level rate profile 仍可能不同。 這代表他們在相同內容品質下，實際消耗的 RB 預算不一定一樣。 對 multicast 來說，這種「成本差」比表面的 CQI 差更關鍵。

分群還受時間脈絡影響

previous quality、移動趨勢、歷史衝突與服務狀態，都可能改變 split 是否值得。 這些資訊幾乎都不會出現在一個單點 CQI 裡，所以 CQI-only 很容易低估真正該分群的情況。

問題不是「CQI 完全沒用」，而是「只靠 CQI 無法完整代表 multicast allocation 的決策難度」。
Resource-Cost

什麼是 resource-cost，為什麼它是目前最實用的主角方法

定義

resource-cost 不是單純再看一次 CQI，而是把使用者的無線條件轉成 「若要提供某種服務品質，大概要付出多少資源」的表示。 它是比較接近 allocator 語言的 feature，不是單純的 channel 外觀。

價值

multicast grouping 真正要解的是「把哪些人綁在一起最划算」。 resource-cost 直接描述這件事，因此通常比 CQI-only 更貼近問題本質， 也是目前最有說服力的 practical baseline。

它補到 CQI-only 看不到的地方

CQI 只回答「看起來好不好」，resource-cost 進一步回答「實際上貴不貴」。 這讓分群不再只是找訊號相近的人，而是找資源行為相近的人。

研究上的意義

如果 resource-cost 已經能穩定優於 CQI-only，這就證明： 問題 formulation 的提升，本身就值得成為研究貢獻，不一定非要靠複雜 learner 才算成果。

Multi-Feature

什麼是 multi-feature，它比 resource-cost 再往前走了一步

定義

multi-feature 的想法是：不要把分群壓成單一 scalar，而是保留多種與決策相關的狀態， 例如 CQI history、RB-level rate profile、previous quality、mobility 狀態、 以及衍生的 resource-cost 訊號。

價值

有些 split-worthiness 並不是單一成本就能完全表達，尤其當問題同時包含 時間脈絡、品質歷史與局部異質性時，multi-feature 能保留更多真正影響 grouping 的結構。

它和 resource-cost 的差別

resource-cost 比較像「最貼近 allocator 的單一主軸」； multi-feature 則是承認問題本身可能不只一個主軸， 因此用更完整的 feature space 來描述使用者之間的差異。

它的研究意義

multi-feature 表示我們的主線，已經從「學模型」轉成「設計更好的 grouping representation」。 即使最後不用 learner，這條路也依然能形成一個完整而合理的研究故事。

Feature 定義

目前的 multi-feature 到底是哪幾個 feature

這裡要先分清楚兩件事。現在主比較表中的 Multi-feature k-means， 在 [le_gra_mvp.py](C:/Users/Weber/Documents/LE-GRA-MVP/le_gra_mvp.py) 裡固定使用的是 feature_mode="full"； 但目前 coupled learner 的 LE-GRA 訓練腳本，預設使用的是 feature_mode="history_cost_quality"。 兩者都叫 feature-based，但輸入並不完全相同。

Multi-feature k-means 使用的 `full`

  • `cqi_history`：5 維，代表最近 5 個時間點的 CQI。
  • `rb_stats`：4 維，分別是每位使用者 RB rate 的 mean、min、max、std。
  • `mobility`：3 維，分別是 distance、speed、direction_to_gnb。
  • `cost_vec`：6 維，對應 6 個影片品質層級的 resource-cost。

所以 `full` 總共有 18 維，它不是單看當前通道， 而是把時間、頻域、移動狀態與資源成本一起看。

LE-GRA learner 預設的 `history_cost_quality`

  • `cqi_history`：5 維。
  • `cost_vec`：6 維。
  • `previous_quality`：1 維，正規化後表示前一輪品質狀態。

這組總共 12 維。它比 `full` 更精簡，保留我們認為最直接跟 teacher 決策、 switching penalty 與 service difficulty 有關的核心訊號。

Resource-Cost 公式

resource-cost 是什麼、公式怎麼寫、它代表什麼

在實作上，resource-cost 來自 [le_gra_mvp.py](C:/Users/Weber/Documents/LE-GRA-MVP/le_gra_mvp.py) 的 user_resource_cost_vector()。它的意義是： 對每個使用者、每個影片品質層級，估計最少需要多少個 RB 才能把該 bitrate 送出去。

設影片品質 q 的目標 bitrate 為 B_q，
使用者 u 在各 RB 的可達速率為 r_u,1, r_u,2, ..., r_u,R，先由大到小排序成 r_u,(1) ≥ r_u,(2) ≥ ... ≥ r_u,(R)。

則 resource-cost 定義為：
c(u, q) = min { m | Σ[j=1..m] r_u,(j) ≥ B_q }
若全部 RB 加總仍不足，則記為 R + 1（代表此品質層不可行）。

這個公式為什麼合理

multicast allocator 最後真正在決定的，是每組使用者在有限 RB 下能被服務到哪個品質層。 所以比起問「這個人 CQI 幾分」，更直接的問題其實是 「如果我要把他服務到 720p、1080p，分別要花多少 RB？」。 resource-cost 正是在用一個可計算、可比較的形式回答這件事。

它實際代表什麼

它代表的是 服務難度，不是單純的訊號外觀。 兩個使用者就算 wideband CQI 很接近，只要 RB-level profile 不同， 對不同品質層所需的最少 RB 數也可能不同。這正是 CQI-only 看不到、但 allocator 很在意的差異。

另外要注意，在 feature matrix 裡使用的 `cost_vec` 會再除以 RB 數量 `R`， 也就是把「需要幾個 RB」轉成「大約需要幾成 RB」。 這樣不同場景之間更容易比較；但在 `Resource-cost k-means` baseline 本身， k-means 直接吃的是原始 cost vector。

為什麼選這組

為什麼最後決定使用這些 feature

每一類 feature 對應一個結構性盲點

  • `cqi_history`：補足「只看當下 CQI」看不到的時間趨勢。
  • `rb_stats`：補足 wideband CQI 看不到的頻域 dispersion 與 selective fading。
  • `mobility`：補足未來狀態變化與連線穩定性線索。
  • `cost_vec`：直接把問題拉到 allocator 的成本語言。
  • `previous_quality`：補足 switching penalty，因為 utility 裡明確會扣切換代價。

為什麼不是把所有欄位都塞進去

repo 裡其實還有 `full_context`、`full_radio_context` 這些更大的 ablation 版本， 會加入 `rb_available`、`rsrp`、`rsrq`、`wideband_sinr`、`mcs`、`rb_sinr` 等訊號。 但目前主比較線沒有直接把它們當標準 `multi-feature`， 因為那會混入更多 trace-specific 或 scenario-wide context。

目前主線選擇 `full`，可以理解成一個比較乾淨的折衷： 它已經比 CQI-only 豐富很多，但仍然主要聚焦在每位使用者本身的可分性，而不是把所有外生欄位一起塞給 k-means。

Metrics 關聯

這些 feature 跟我們用的 metrics 之間有什麼關聯與 insight

跟 allocation metrics 的關聯

  • `cost_vec` 最直接對應 `utility`、`ADR`、`rb_utilization`，因為它本身就在近似「到達各品質所需的 RB 代價」。
  • `previous_quality` 最直接對應 `avg_switching` 與 `utility`，因為 utility 公式裡有切換懲罰。
  • `rb_stats` 與 `cost_vec` 一起影響 `served_ratio`、`average_quality` 與 `fairness`，因為它們會改變哪些人適合被綁成同組。
  • `mobility` 與 `cqi_history` 比較偏向提升分組穩定性，減少因瞬時狀態誤判造成的品質震盪。

跟 teacher imitation metrics 的關聯

  • `pairwise_accuracy`：看兩兩使用者是否被正確判成同組或不同組。
  • `ARI`：看整體 partition 結構是否接近 teacher，會校正隨機一致性。
  • `NMI`：看 teacher 與預測分群共享了多少資訊量，較不受 label id 影響。

這三個 imitation metrics 的存在，是因為有些 feature 會先提升「像不像 teacher 的分組結構」， 但未必立刻在 utility 上拉出很大差距；反過來也可能出現 utility 接近、但群組語意不同的情況。

目前最重要的 insight 是： resource-cost 比較像直接對齊 allocation objective 的 feature； multi-feature 則比較像提高 teacher 結構可辨識性的 representation。 前者通常更容易在 utility 類指標上有說服力，後者則更適合支持 「CQI-only 的表示太薄」這個研究主張。

研究流程

整個系統現在的穩定骨幹是 teacher + DP

建立資料與場景

先建立 synthetic 或 coupled trace-like 場景，整理出 CQI history、RB-level rate、 mobility、previous quality，以及各種可用來分群的衍生特徵。

用 offline teacher 給出分群參考

teacher 先依 service difficulty 排序，再搜尋 contiguous cut， 並透過 exact DP allocator 計算每個 candidate grouping 的效益。 這讓 teacher 成為一個可解釋、可重現的 supervision reference。

在同一個 backend 下公平比較方法

把 CQI k-means、resource-cost k-means、multi-feature k-means 與 LE-GRA 全部放到同一套 allocator 下比較，這樣才能把差異乾淨地歸因到 grouping 本身。

因此研究重心回到 feature，不再硬推 learner

learner 分支有其探索價值，但目前最清楚、最穩健的發現， 來自更好的 feature representation，而不是更多 learner-side tweak。

Teacher 設計

為什麼 offline teacher 不追求全域最佳解

teacher 沒有直接搜尋所有可能 partition，原因不是理論上不想做，而是計算量太高。 若對 n 個使用者做 unrestricted partition search，候選數會接近 S(n, k) 等級，會隨使用者數快速爆炸。

真正全域搜尋

約為 S(n, k)

這代表要枚舉所有可能群組切分，對 teacher labeling 來說太昂貴， 不適合作為大量資料上的日常 supervision 流程。

現在採用的 constrained teacher

固定 k 時約為 C(n - 1, k - 1)

先依 service difficulty 排序，再只搜尋 contiguous cut， 就能把搜尋空間大幅縮小，同時保留可解釋性與穩定性。 這不是全域最優，但已經是很強的 constrained optimum。

方法定位

現在這條研究主線的角色分工

CQI k-means

保留作為最基本 baseline。它的重要性在於讓我們看見： 當 feature 太單薄時，grouping 很容易失真。

Resource-cost k-means

這是目前最強、最實用、也最容易論述的主方法。 它把 grouping 問題從「看起來像不像」推進到「服務起來貴不貴」。

Multi-feature k-means

這是更完整的表示路線，證明就算不把主角放在 learner， 只要 feature 設計夠對，仍然能得到更合理的 grouping。

LE-GRA 狀態

LE-GRA 的價值還在，但它不再是主標題

不能再主張什麼

目前沒有足夠證據支持 LE-GRA 是一個穩定、廣泛、普遍優於強 baseline 的通解。 如果繼續把它當唯一主角，論述會變得不夠誠實。

它仍然留下什麼價值

LE-GRA 幫我們看見了 teacher split 的困難區、boundary regime 的特性， 也幫我們釐清很多 learner-side tweak 為何無法真正解決表示不足的問題。

因此最合適的寫法是： 把 LE-GRA 放在 exploratory branch 或 appendix， 而把 resource-cost 與 multi-feature 放在主線敘事中心。

階段結論

這一階段真正交出的成果是什麼

正向成果

  • 建立了穩定的 teacher + DP 比較框架。
  • 證明 CQI-only 不足以代表 multicast grouping 的真實難度。
  • 把 resource-cost 與 multi-feature 推成更合理的主方法。

誠實限制

  • LE-GRA 沒有成長為一個可穩定主打的通用 learner。
  • 不是所有 regime 都真的需要複雜 split。
  • 研究價值更明顯地落在 feature representation，而不是純 learner design。
主線定位：用 teacher + DP 驗證 richer feature-based grouping 的價值
核心訊息：比起再硬推 learner，resource-cost 與 multi-feature 更能代表這個專案目前最有說服力的成果
